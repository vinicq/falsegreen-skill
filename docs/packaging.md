# Packaging and Release

This project has one canonical protocol and several host-specific packages.
Keep the protocol in one place, then expose thin entry points for each host.

## Canonical Files

- `SKILL.md` - source of truth for the J1-J6 protocol.
- `reference.md` - full pattern catalog and look-alike exemptions.
- `schema/finding.json` - source of truth for a single JSON finding.
- `schema/report.json` - source of truth for machine-readable reports.
- `llm.md` - self-contained prompt context used by the CLI and API examples.

When the protocol changes, update `SKILL.md` first, then sync any compact
contexts that intentionally duplicate protocol details.

## Host Targets

| Target | Files | Notes |
|---|---|---|
| Claude Code plugin | `.claude-plugin/`, `skills/falsegreen-llm/SKILL.md` | Plugin skill entry point. The skill lives at `skills/<name>/SKILL.md`. |
| Claude.ai / Anthropic API Skill | generated by `npm run build:targets` into `dist/claude-agent-skill/` | Standalone package with `SKILL.md` at package root. |
| Codex plugin | `.codex-plugin/plugin.json`, `skills/falsegreen-llm/SKILL.md` | Manifest must declare `"skills": "./skills/"`. |
| Gemini CLI extension | `gemini-extension.json`, `GEMINI.md` | Extension context, not the same as a Gemini Agent Skill. |
| Gemini Agent Skill | `.gemini/skills/falsegreen-skill/SKILL.md` | Workspace skill entry point. Standalone copy is generated into `dist/gemini-skill/`. |
| Cursor | `contexts/cursor.md` | Contains the `.cursor/rules/*.mdc` template. |
| CLI | `bin/falsegreen-llm.js`, `llm.md`, `schema/` | Supports `--json` validation against the canonical schemas. |

## Context Policy

The maintained context files are:

- `contexts/claude.md`
- `contexts/codex.md`
- `contexts/gemini.md`
- `contexts/cursor.md`

Do not add generic provider contexts. If a provider is not an official target,
keep it in CLI/provider examples only when there is a clear maintenance reason.

## Scripts

Run before release:

```bash
npm run validate
```

This checks required files, skill frontmatter, Codex/Gemini manifests, schema
shape, legacy JSON field names, and unsupported language claims.

Build standalone host packages:

```bash
npm run build:targets
```

This writes generated packages under `dist/`. The `dist/` directory is ignored
by git and should not be committed.

## JSON Contract

All machine-readable output must conform to `schema/report.json`.

Finding fields use:

- `case`
- `judgment`
- `confidence`
- `language`
- `intent`
- `test.name`
- `finding`
- `evidence[]`
- `oracle` for semantic case `18`
- `fix_hint`

Do not reintroduce legacy names such as `case_id`, `judgment_failed`, or
`test_name`.

Use `C18` only for the structural `str()`/`repr()` comparison code. Use `18`
for the semantic spec-contradiction case. `oracle` is required only for `18`.

## Release Checklist

1. Run `npm run validate`.
2. Run `node --check bin/falsegreen-llm.js`.
3. Run `node --check scripts/validate-package.mjs`.
4. Run `node --check scripts/build-targets.mjs`.
5. Optionally run `npm run build:targets` and inspect `dist/`.
6. Delete generated `dist/` before committing unless a release process explicitly
   requires keeping it outside git.
7. Check `git status --short` for unrelated files.
8. Commit by target area: packaging, contexts/docs, CLI/schema validation.
